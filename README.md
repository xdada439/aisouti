# AI 搜题（aisouti）

Android 端**离线优先**的答题辅助悬浮窗。在任意刷题 App 上点一下悬浮球，应用静默截屏、识别屏幕上的题目、在**本机题库**里检索答案，直接显示在悬浮窗上。

主要卖点是**本地命中**：题库存在设备上，不联网、不花钱、约 400ms 出结果。大模型只是补充——只有本地路径全部失手时才会调用。

- 请在**符合所在学校、机构、考试组织方规定**的前提下使用。因在禁止使用辅助工具的场合使用而产生的一切后果，由使用者自行承担。

- 不收集任何数据，无账号体系，不生成设备指纹。所有内容存于设备本地。

- 大模型给出的答案**不保证正确**。凡是没有题库依据的答案，悬浮窗都会标注「题库未检索到，依据视觉/语言模型判断」。

## 工作原理

分**识别层**和**答案层**两级，任何识别路线产出同一种结构化题目，都汇入同一个答案层。

### 识别层：三条路线，串行降级

```
点击悬浮球 → 抓悬浮球 Y 坐标 → 隐藏悬浮球 → 静默截屏
  （Android 11+ 用无障碍截屏；失败降级 MediaProjection）
        │
        ├─ ① OCR        ML Kit 中文，离线免费，~400ms
        ├─ ② Vision     用户配置的多模态模型，联网计费，~3s
        └─ ③ 无障碍节点  直接读控件树文本，离线免费（截屏不可用时兜底）
```

OCR 路线的核心是**白名单提取**：以选项为锚点向上回溯圈定题干，边界外一律丢弃。顶部导航、底部答案泄露、共用材料都被边界天然挡在外面。

其中 `util/OcrLayout.kt` 做**版面重建**——不信任 OCR 引擎给的行划分，按 y 区间重叠把文本块并回「屏幕上真正的一行」。这一步是跨 App 稳定性的地基：不同刷题 App 的选项版面差异很大（标签与内容分离、内容换行、横排网格），但「一行」这个几何概念是通用的。

一屏多题时，用**悬浮球的 Y 坐标**决定搜哪一道。

### 答案层：三级降级

```
① 精准题库（本地 SQLite）   score ≥ 0.30 且题型兼容 → 命中
     ↓ miss
② 资料 RAG + LLM 判答        首块相关度 ≥ 0.45 才投喂
     ↓ miss
③ 模型自身知识兜底           答案带「题库未检索到，依据 X 判断」提示
     ↓ 仍无
   "无法判断"
```

题库检索用五层召回（选项内容 / 4 字滑窗 / bigram AND / bigram OR / 全表），并按**选项内容**把题库的 ABCD 重映射到屏幕上的 ABCD——题库和屏幕的选项顺序常常不一致。

**只支持单选、多选、判断三种题型。**

## 快速开始

### 构建

```bash
./gradlew :app:assembleDebug
```

需要 JDK 17。Release 签名读根目录 `keystore.properties`，文件不存在时自动跳过签名配置，不影响构建。

| 项 | 值 |
|---|---|
| compileSdk / targetSdk / minSdk | 34 / 34 / 21 |
| Gradle / AGP | 9.3.1 / 9.1.1 |

### 授权（三项，都需要手动开）

1. **无障碍服务** —— 用于静默截屏、承载悬浮窗、读取球坐标
2. **悬浮窗权限** —— 显示悬浮球和答案
3. **忽略电池优化** —— 防止后台被杀

> 注意：重装 APK 后部分 ROM（如 ColorOS）会自动关闭无障碍服务，需要重新开启。

### 导入题库

主页 →「导入资料」→ 选择 xlsx。兼容常见刷题模板，表头需含题干、选项、答案等列。资料库（用于 RAG 模糊匹配）支持 txt / xlsx / docx / pdf。

**题库是本应用的核心。** 没有题库时也能用，但每道题都要走大模型，慢且不保证正确。

### 配置 AI 接口（可选）

主页 →「API 配置」。点服务商预设会自动填好地址和模型名，你只需填自己的 API Key。

| 服务商 | 视觉模型示例 | 备注 |
|---|---|---|
| 通义千问 | `qwen-vl-max` | 阿里云百炼控制台获取 Key |
| 豆包 | `doubao-1.5-vision-pro-32k` | 模型名要填接入点 ID（`ep-` 开头） |
| 智谱 GLM | `glm-4v-plus` | |
| Kimi | `moonshot-v1-8k-vision-preview` | 需用带 vision 的模型名 |
| OpenAI | `gpt-4o` | 国内通常需代理或中转 |
| SiliconFlow | `Qwen/Qwen2.5-VL-72B-Instruct` | 模型名要带组织前缀 |

只要是 **OpenAI 兼容**的 `/chat/completions` 接口都能接，不限于上表。填完点「测试连接」会先测文本连通性，再**实际发一张图**验证读图能力——只填了纯文本模型时会明确告知。

**视觉模型和文本模型建议都填。** 文本模型用于资料判答和兜底推理，用视觉模型干这个又慢又不擅长。

## 代码地图

```
app/src/main/java/com/lk/studyassistant/quantum/
├── service/     核心链路。FloatingWindowService 是搜题主流程
├── floating/    悬浮窗 UI 与答案渲染
├── local/       本地数据层：题库检索打分、资料 RAG、文本归一化
├── util/        识别工具：OCR 引擎、版面重建、节点树提取、提示词与解析
├── data/        API 配置、LLM 调用、显示设置、识别日志
└── security/    悬浮窗防截屏（FLAG_SECURE）
```

`backend/` 是配套的 Python FastAPI 后台（题库管理 + RAG），**App 与它完全脱钩**，不导入题库到手机的话可以忽略整个目录。

## 排查问题

用户中心 →「识别日志」，保留最近 3 次启动的搜题记录，可一键复制。

按这个顺序看：

| 日志 tag | 看什么 |
|---|---|
| `[Pipeline]` | 走了哪条路（OCR / Vision / 无障碍） |
| `[OcrLayout]` `[OcrDump]` | 版面重建效果、OCR 原始行结构（仅解析失败时输出） |
| `[Extract]` | 题目被识别成什么样（题干 / 选项 / 题型） |
| `[QuestionBank]` | 候选分数、题型、`candidate_dist` 分布 |
| `[Stats]` | 会话级降级率，换 App 时命中率变化一眼可见 |

也可以接 logcat：`adb logcat -s AI_SOUTI`
